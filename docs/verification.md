- `cargo test --locked --workspace`：28 个 Rust 测试通过。
- `cargo fmt --all -- --check`、`cargo clippy --locked --workspace --all-targets -- -D warnings`：通过。

Rust 测试包含真实 HTTP/WebSocket 服务，覆盖公开/隐藏节点、访客字段隔离、跨站写入拒绝、登录限流、Token 换发、重连补传、PSI 事件与回放、多个观察点的候选关联、主题导入与配置、备份恢复和无效备份拒绝。Webhook 测试使用本地接收器，验证失败重试、去重、宽限期与恢复通知，没有向真实联系人发送通知。

## 真实 Linux 部署

测试环境为 Debian 13 x86_64、2 核、约 2 GiB 内存。Hub 与 Agent 使用独立 systemd 服务和专用账户，Hub 监听回环地址，通过 SSH 转发预览。

- Agent 上报真实 CPU、内存、磁盘、网络、连接数、进程数和 PSI；内存总量与 `/proc/meminfo` 一致。
- 节点在后台和公开页显示在线且采样新鲜；公开响应不含地址、主机名、私有备注、Token、boot_id 或内核累计计数器。
- 热添加 TCP、DNS、TLS、HTTP 任务，Agent 收到任务后返回分段耗时。IPv4 TCP/HTTP、域名 DNS、证书校验 TLS，以及 IPv6 回环 TCP/HTTP 均成功；HTTP 返回 200。临时任务与 IPv6 测试服务已清理。
- 重启测试 Agent 后，故障时间线记录连接中断和恢复。导出的独立报告包含 120 个真实采样，节点标识匿名化，图表与回放滑块可正常使用。
- 安装后的 Hub/Agent 以及服务器原有的 `komari-agent`、`soga` 服务处于运行状态。
- 在隔离实例中实测两个 systemd 安装器及卸载器：Hub 启动健康，卸载保留数据库；Agent 成功采集真实数据，卸载移除程序、服务与凭证文件。临时实例和账户已清理。

这是单台测试机的功能验证，没有进行大规模节点、长期数据增长或公网 IPv6 的容量验证。

## 浏览器验证

在真实 Hub/Agent 上验证了登录、创建节点、一次性安装凭证弹窗、编辑保存、分组与搜索空状态、总览、资源历史、探测任务、主题和设置页面。

独立诊断 HTML 通过静态文件服务打开，确认匿名观察点、恢复状态、资源曲线、采样表与滑块末端数据。公开页在 390 px 视口下的页面宽度等于视口宽度，没有页面级横向溢出。

截图与诊断样本保存在工作区 `artifacts/`，不纳入源码提交。诊断报告为脱敏数据；数据库备份不属于脱敏报告。

## 交付边界

Linux x86_64 已实际运行。ARM64 代码与安装路径已提供，尚未在 ARM64 服务器上运行；macOS Agent 仅用于显式 `--dev` 验证。公网域名、反向代理证书和真实 Telegram 渠道尚未配置。

单 Hub 停机不能自行告警；内存补传不能恢复 Agent 重启或断电丢失的采样。多个节点异常是排查线索，预测用量不等于账单。完整数据语义见 `protocol.md`。

## 后台管理更新（2026-10-06）

默认主题在管理列表中改名为“默认主题”，移除简洁主题选项，并删除测试实例中其他已安装主题。后台默认进入节点管理，列表只展示管理信息；原生节点详情入口转入编辑配置。网络后台仅展示任务配置，系统设置分为站点、通知、安全和数据四栏。

在实际 Linux Hub 的浏览器中，用两个临时私有节点验证拖动排序、数据库保存及刷新后的顺序；编辑弹窗切换分类后保留输入。临时节点已删除，真实节点及其原有顺序保留。移动端直接显示名称、状态与操作，无页面横向溢出。Rust 测试覆盖排序事务、无效或过期列表拒绝、稳定节点编号及公开主题排序字段；前端测试覆盖筛选列表排序时保留其他节点位置。
